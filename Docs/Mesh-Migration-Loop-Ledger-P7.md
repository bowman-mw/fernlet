- `FernletLockState` carries associated values (`.locked(cooldownDeadline:)`, `.unlocked(scope:)`); the policy takes the projection `appLockEngaged: Bool` (true iff `.locked`), which is exactly how `shouldRunPresence` / `shouldListenForRecipeShares` read it today.

- `ContentView` already mirrors `lockService.state` into `store.lockState` (`handleLockStateChange`) and `isDuressSessionActive` into `store.duressSessionActive` — the tab mirror is the third of that family, not a new pattern.
