## Surprises worth not re-deriving
- **No Swift toolchain in this session's container** (see the environment line). Compile correctness is by reading declarations, never by building; the verifier's first job on every item is "would this compile".
- The Xcode project uses `PBXFileSystemSynchronizedRootGroup` for `App/Fernlet` and `Tests/FernletTests` — a new `.swift` file under either is in its target with **no pbxproj edit**.
- **The app target is `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` + `SWIFT_APPROACHABLE_CONCURRENCY = YES`** (⇒ inferred isolated conformances, SE-0470); `FernletTests` has approachable concurrency but NO default isolation. Invariant measured at item 1: every `nonisolated` Equatable/Hashable/Codable type in `App/Fernlet` stores only explicitly `nonisolated` types — a new one that stores an un-annotated app enum (e.g. `FernletTab`) is a likely compile error. Mark the stored enum `nonisolated`, not the container `@MainActor`.
- **An input struct that stores the foreground Bool collapses `.active`/`.inactive` into one value.** A product enumerated over 3 phases yields 2/3 that many distinct inputs; pin the distinct count as its own literal, never `== rowsEnumerated`.
- **A matrix oracle that reads the policy's computed inputs or repeats its argument expressions is a tautology** (item 1's pass A: 0 mismatches by construction). The oracle takes the RAW inputs, spells the SHIPPING predicates where §13 is silent, and the mismatch set — pinned by count and by shape — is the asserted deviation. Same trap one level up (item 2's pass A): a host cell that recomputes `decide(host.inputs)` against what the host wrote can never fail — the expectation must be a LITERAL gate per step.
- **A "single writer" wall that collects file NAMES is green with two call sites in one file** (item 2's pass A). Count occurrences across the sweep and pin the total at 1, beside the file-list claim.
- **A receiver-qualified needle (`store.recipeShareManager.start()`) is blind to the same object under another name** (`manager.start()` in `ProximityRecipeShareSheet`, item 3 pass B — a real second owner whose restart guard read `lockService.state`, which is `.unlocked` during duress). Sweep receiver-agnostically in every file that names the manager type or property, and exempt by file name with a pinned count.
- **Delete-all now re-arms the radios the instant its leg falls** — safe because `wipeIdentityForDeleteAll()` (leg 11) runs before the hook's `defer`, so a fresh search advertises the NEW identity; today's app advertised the old one through the whole wipe. Duress stays latched (the lock leg keeps `demandsTeardown`), below-age clears only on a new record.
- **Lane C's rejection-matrix harness installs after the launch push and calls `startJoin()` directly**; any later leg change off the Friends tab stands it down. A Lane C run stays on the Friends tab (or the harness feeds the tab leg).
- **A host leg the host lowers itself can never rise again if the observed predicate never fell** (item 4 pass A: the teardown set liveness false while `isSessionLive` stayed true — `stopJoin()` nils no `currentMesh` and moves no `sessionState` — so `.onChange` had nothing to carry and the poller was dead for that mesh's life). The predicate drives the leg; a door that wants the leg to fall ends the session through the manager's own end path.
- **A self-re-arming one-shot must re-check cancellation AND liveness after the sleep, before the tick** — a continuation already queued on the main actor outlives `cancel()`; a tick can land mid-wipe and re-arm over a fresh `connect`.
- **`startSessionCeiling` had two callers (found, restore) and none on the adopt path** — the yielding founder of §12.3 finding 3 had no ceiling to enforce; a poller that "enforces the ceiling" is hollow for that case until the adopt path arms it from the ADOPTED mesh's `createdAt`.
- **`applyPartitionVerdict` anchors the idle-lapse deadline at `now + 1800`, so no tick can both arm and judge the window** — the consumers' order is pinned by the wall's index assertion, not by any behavioural cell.
- `isolated deinit` has app-target precedent (`NetworkMeshFeasibilityProbe.swift`); a global-actor `static let` of Sendable type is implicitly nonisolated under SE-0434, so a default argument may read it.
- **`rejoinBar` is never cleared while `offersForegroundResume` is** — a global read of the bar names mesh B "ended" with mesh A's bar; the only honest input is `rejoinRefusal(for: <the mesh in hand>)`. **The four restore properties and their three types are internal to ProximityKit** — the mechanical reason no app surface ever read them; a public `MeshSessionRestoreOutcome` would drag `MeshSessionContext` public, so the projection is one small public value, not the types.
