## FernletShareExtension
- Schema drift hazard by design: the extension-side SharedRecipeImportRecord mirror omits the app-side `budgetDeferredDayKey` field, and every enqueue decodes-then-rewrites the WHOLE queue file with the mirror type — so any share silently strips the budget-deferral stamp from every queued record, letting the app re-fetch a budget-deferred page the same day (App/FernletShareExtension/SharedRecipeImportQueueWriter.swift:86-96 vs FernletKit/Sources/AppServices/SharedRecipeImportQueue.swift:23).
- The extension's queue file access is not NSFileCoordinator-coordinated while the app side coordinates every read and write; a concurrent extension enqueue racing the app's drain is last-writer-wins, so an enqueue can be lost or a just-removed/just-annotated record resurrected — the atomic write only prevents torn files (SharedRecipeImportQueueWriter.swift:100-118).
- Fallback-path divergence: when the App-Group container fails to resolve, the extension falls back to NSTemporaryDirectory() but the app-side queue falls back to Application Support first, then tmp — the two processes would then read/write different files (SharedRecipeImportQueueWriter.swift:122-128 vs SharedRecipeImportQueue.swift:188-195).
- Re-sharing a URL already in the queue replaces its record with a fresh never-attempted one, resetting attemptCount to 0 — this restarts the app side's 5-attempt retry cap for a permanently broken page (looks intentional, documented as behavior).
