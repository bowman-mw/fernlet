## Surprises worth not re-deriving
- `LoadToken` is an associated value of `loaded`/`absent` only — `refused`/`deferred`/`corrupt` structurally cannot `save`.
- `isSessionOpen` gates *members*, not *links* (0b, `871b7ee`); `mayLinkToDiscoveredPeers` is the link gate. Relaxing a link gate is only safe on a members-only transport: QUIC is, MC is not — hence `maySeatVerifiedPeer`.
- A joiner's bootstrap root is its ADMITTER's key, not the founder's; `MeshLedgerAdoption.adopt` rebases from the self-admitted root. On a pair the rebase is an unproven no-op — item 14 is the first exercise.
- `.merge` > `.membership` > `.timer` in a 2 s coalescing window; a merge-seeded test cannot then observe a membership rotation (`seedMembershipLedgerForTesting`).
- The keyring stamps supersession INSIDE the rotation whose drain waits ~10 s for acks a fake never sends — bracket grace assertions accordingly.
- `PayloadType` is switched only with `default` (manager + coordinator) — adding a case has no clean-build non-exhaustive-switch hazard.
- Harness: `STAGGER=1`; re-harvest identities after any `xcodebuild test`; fresh log dir per run; `pgrep xcodebuild` before believing a failure; a bare-integer link key is the reliable negative.
- Instrument the wire before believing an inference — "never arrived" and "arrived and refused" read identically without an echo.
- `/loop` never compacts between iterations → fresh session per phase; this ledger is the only durable state.
- Closed; do not re-audit: `MeshTunnelConvergence`, the id-vs-endpoint family (`96337a3`, `2f273a9`), the crypto-purpose / `PayloadType` / record-kind spellings (walled).
- Concurrent sessions share this tree and sim fleet; `Localizable.xcstrings` + `xcschememanagement.plist` are held by another session — never stage them.

## Findings deliberately not fixed (cont.)
- **Cap × forged stamp:** union laws hold at a full `MeshContentSet` because "keep the max k under a fixed total order" composes — *provided* two copies of one ID agree on their ordering keys. The only field copies can differ on is receiver-local `firstSeenAt`, and it reaches `orderingInstant` only when a stamp is clamped (a forged stamp). On a full set that is the single shape where an inner merge could drop the copy an outer merge would keep. Named in `MeshContentSet`'s docs; P5's routed store (which owns first-seen) is where it is settled. Cost: at most one forged-stamp item's position differs across members at the cap; never a genuine one.

- **(P4 i9)** Making `departed` a fourth *stored* delivery state would break the ladder — a max-merge would let a departure overwrite a `delivered`. Derived at read, the merged state stays a clean three-element chain and the ledger stays the only authority on membership. P5 persists the target inside its routed store (its own wipe row); nothing here is `Codable` on purpose. `MeshDeliveryTarget(for:roster:selfFingerprint:)` takes any `MeshMergeableContent` — one call per content event for item 9.

- **(P4 i10)** **The property test earned its keep on iteration A** — it found the 2c deadlock (a genuine shipping merge bug none of items 2–8's targeted tests reached). Two rig lessons: `presentedEpochHeads` legitimately **differs** per member (`unresolvedEpochHeads` drops heads ≤ own counter as resolved), so the merged-state claim is `rotationBasisHead`, not the raw head set — a checker on the raw set produced 40 false failures; and a healed partition must be **re-formed as a full mesh with a second commit round**, because §10.2's branch scoping reads presence — a member on a partial reachable set elects a *different* coordinator. Inside the parallel full run the new suites' banners read 95–132 s of *elapsed*, but they are pure values with no `await` — 4.9 s alone; suite total did not regress.

- **(P4 i11)** **Merge-window liveness residual** (not a convergence defect): in the 2c shape *no* window ever closes — the responder ends the scenario still `awaitingResumeMerge` — so for the rest of that session that device opens **no further blip exchange** and later records take the merge path. Bounded by `abandonMergeExchange` (re-split) and `resetSessionStateMachine` (new session). 9b's nested re-split walks through it; if it ever needs to close, the safe place is a responder-side "answered *and* the peer's next digest matched" rule, never "answered" alone (that would route later records down the live path and rotate `.membership` per record).

- **(P4 i12)** `beginMergeExchange` asks only the slots that exist **when it runs**; anything seated later must be asked one-off (`askOneReconnectedPeer`). `reGossipedToFingerprints` is session-scoped and an abandon does **not** reset it — a re-plan after a re-split must prefer pairs the first heal never used, and sub-branches that mint a membership record after an abandon have no proactive push (the epoch-heads half has no such gate, which is what re-converges heads). `MeshPartitionShape` derives roster from branch sizes; §16.2's shape list is closed. A commit-round loop must exit on bases **and** rosters agreeing, not epochs alone.
